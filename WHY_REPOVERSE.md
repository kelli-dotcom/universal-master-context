# Why this is the Repoverse

Repoverse means a universe made of repos.

Kelli does not build one big app and stop. She sees a problem or a
possibility, she makes a folder for it, and that folder becomes a repo.
Feather Themes is one piece. Feather Speed is one piece. Stack
Blueprints is one piece. Agent Etiquette is one piece. Openflex is
one piece. GetCrowd is one piece. Each one solves one job, in plain
words, with no bloat.

The problem was that each piece started from scratch. A file that
existed in one repo was missing in the next one. She kept finding
out later that a repo was missing a README, or a changelog, or an
ignore file, or a test. The idea was there, the folder was there,
but the rest of the repo was not.

This master is the seed for the whole universe. Copy it, put your
idea in the middle, and the rest is already there. The next repo
starts complete, not half built.

That is also why it is a fractal. A fractal is the same shape at
every size. The master has the same shape as every repo built from
it: a front door, rules for helpers, a place for the work, a place
for the checks, and a place for what changed. A small kit and a big
app both use the same shape, just with different code in the middle.
And a repo built from this master can become a piece for the next
one, the same way feather-themes became a piece for openflex.

The name lives up when three things are true.

1. Every new repo starts from this master, not from an empty folder.
2. Every file in the master came from one of her own repos, not
   from a generic list on the web.
3. Nothing in the master is dead weight. Every file earns its place,
   or it is left out.

If a new repo starts empty, or a file is copied in just because
other people have it, the name does not live up. That is the check
to run before any new repo is called part of the repoverse.
